# Current State — what's real vs. what's a stub

Written at handoff time so the next agent doesn't waste time rediscovering this by reading every file.
**Nothing in `Sources/` contains real logic yet.** This package is a scaffold + a complete knowledge
base, not a partially-built app. Do not assume any Swift file exists beyond what's listed here.

## What does NOT exist yet (i.e., everything else)

- No protocol implementation (`PxcFrame`, `PxcHandshake`, `BikeProfile`, `QrData`, `RsaKeys`) — zero
  Swift code written.
- No networking (`EasyConnProber`, TCP listeners, Wi-Fi join flow) — zero Swift code written.
- No video pipeline (`H264Encoder`, `NavigationCompositor`, `FrameQueue`) — zero Swift code written.
- No MapKit integration — zero Swift code written.
- No trip logging, media button bridge, adaptive bitrate controller, settings/persistence — zero Swift
  code written.
- No real UI beyond the one placeholder view — zero Swift code written.
- No unit tests — zero Swift code written.
- No app icon, no App Store Connect record, no registered Bundle ID (that last one is a manual Miel task,
  see above).
- **This project has never been opened in Xcode or built even once.** `project.yml` has not been run
  through `xcodegen generate` and the result has not been compiled. Treat the very first `xcodegen
  generate && xcodebuild build` as a real unknown, not a formality — there may be XcodeGen syntax
  mistakes or missing keys that only surface at that point. Fix forward; this doc's job is to save you
  re-deriving the *design decisions*, not to guarantee zero bugs in the config files.

## Recommended first session

Per the phased build order in `docs/02-IOS-ARCHITECTURE-PLAN.md`:

1. Run `xcodegen generate` and get a clean `xcodebuild build` on the placeholder app first — confirms
   the scaffold itself is sound before adding real code on top of it.
2. Write `Sources/Protocol/PxcFrame.swift` + a unit test (`Tests/PxcFrameTests.swift`) that round-trips
   encode/decode and verifies the magic-XOR rejection path — this has zero dependencies and is fully
   testable in the simulator/CI without a bike.
3. Continue down the phased build order.
